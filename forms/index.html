Hva gjør serveren med det?


app.post('/api/spill', (req, res) => {
  const { tittel, plattform, timer } = req.body;

  db.prepare(
    'INSERT INTO spill (tittel, plattform, timer) VALUES (?, ?, ?)'
  ).run(tittel, plattform, Number(timer));

  res.status(201).json({ tittel, plattform, timer: Number(timer) });
});

Plukk ut verdiene du trenger – ikke send hele req.body rett inn i databasen

  • Linje 2: vi plukker ut akkurat de tre feltene vi vil ha. Alt annet som måtte ligge i body-en, blir ignorert.
  • Number(timer): skjemaet sender alt som tekst – husk "40" fra FormData-demoen.
  • Poenget: serveren bestemmer hva som går inn i databasen, ikke den som sender.

Må det hete det samme overalt?

Skjemaet JavaScript Databasen
name="tittel" tittel: 'Zelda' tittel TEXT
timer = "40" (tekst!) timer: 40 antall_timer INTEGER
plattform = "Switch" plattform: 'Switch' plattform_id = 3

Nei. Hvert lag har sitt eget språk.

Tall kommer som tekst fra skjemaet. Og databasen kan lagre et id-nummer der brukeren ser et navn.

Du oversetter på grensa


// Inn: fra API-et til databasen
const { tittel, timer } = req.body;
db.prepare('INSERT INTO spill (tittel, antall_timer) VALUES (?, ?)')
  .run(tittel, Number(timer));

// Ut: fra databasen til API-et
const rader = db.prepare('SELECT tittel, antall_timer FROM spill').all();
res.json(rader.map((rad) => ({
  tittel: rad.tittel,
  timer: rad.antall_timer,
})));

Eller rett i SQL: SELECT antall_timer AS timer

Serveren er grensa mellom API-et og databasen. Inn: plukk ut feltene fra req.body og legg dem i riktige kolonner. Ut: plukk ut kolonnene og gi dem navnene API-et lover.

Det du ser på skjermen er treet – og treet kan endres

Treet heter DOM. Hver tagg er en node. tbody#rader er en gren uten noe på – ennå.

Tre verb


const tr = document.createElement('tr');
const td = document.createElement('td');
td.textContent = 'Zelda';
tr.append(td);
rader.append(tr);
Det du ser
Tittel

Treet

Laget, men ikke festet

  • createElement: raden finnes – men i den røde boksen. Ingen ser den.
  • En celle. Løs, den også.
  • textContent: cella har fått tekst. Fortsatt usynlig.
  • append: cella henger i raden. Raden henger fortsatt ikke i sida.
  • Først nå, når raden henges på tbody, dukker den opp.

Plukk ut feltene du vil vise


function lagRad(spill) {
  const tr = document.createElement('tr');
  tr.append(
    celle(spill.tittel),
    celle(spill.plattform),
    celle(spill.timer),
  );
  return tr;
}

function celle(tekst) {
  const td = document.createElement('td');
  td.textContent = tekst;
  return td;
}

for (const spill of alle) {
  rader.append(lagRad(spill));
}

Du bestemmer hva som vises, og i hvilken rekkefølge – uansett hva API-et sender

Samme tanke som på serveren: plukk ut verdiene du trenger. Kommer det en id eller andre felt med fra API-et, vises de ikke – fordi vi ikke plukket dem.

Snarveien: Object.values


function lagRad(spill) {
  const tr = document.createElement('tr');
  for (const verdi of Object.values(spill)) {
    const td = document.createElement('td');
    td.textContent = verdi;
    tr.append(td);
  }
  return tr;
}

Kortere – men da bestemmer SELECT-en hva som vises, og i hvilken rekkefølge

Oppgave 10 i time 13 bruker snarveien, og testen krever alle feltene i samme rekkefølge som i SELECT-en. Den tydelige versjonen består også, så lenge alle feltene er med i riktig rekkefølge. NB: begge er løsningen på oppgave 10 – vis dem etter at de har prøvd selv.

Hva skjer hvis noen skriver <b>hei</b>?


Det som visesMetode

textContent: teksten er alltid bare tekst. innerHTML: nettleseren tolker den – og kjører den. Det heter XSS.

Legg til <b>hei</b> med begge. Så img-knappen, og innerHTML: alerten kommer. Tenk deg at den kom fra skjemaet til en annen elev – og kjørte hos alle som åpnet sida.
